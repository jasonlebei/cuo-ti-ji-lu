# 🐍 Python 基础知识：贪心算法在找零问题中的应用

在处理“货币找零”或“最少货币数”问题时，通常采用 **贪心算法（Greedy Algorithm）**：即优先使用面额最大的货币，剩下的余额再依次使用较小面额的货币。

---

## 📝 题目回顾

**8、某货币由 5 元，2 元和 1 元组成。输入货币总金额，计算出总货币数最少的币种组成。为实现其功能，横线处应填入代码是（）**

```python
N = int(input())
M5 = N // 5
M2 = ________
M1 = ________
print(f"5*{M5}+2*{M2}+1*{M1}")
```

* A. 第 1 横线处应填入：`N // 2`；第 2 横线处应填入：`N - M5 - M2`
* B. **第 1 横线处应填入：`(N - M5 * 5) // 2`；第 2 横线处应填入：`N - M5 * 5 - M2 * 2` (√)**
* C. 第 1 横线处应填入：`N - M5 * 5 // 2`；第 2 横线处应填入：`N - M5 * 5 - M2 * 2`
* D. 第 1 横线处应填入：`(N - M5 * 5) // 2`；第 2 横线处应填入：`N - M5 - M2`

**解析**：
* **你的答案**：A
* **正确答案**：B

---

## 🔍 核心考点深度拆解

### 1. 余额的迭代计算
找零问题的核心在于：**每一步计算必须基于“剩余的金额”**。

* 初始金额为 `N`。
* 选完 5 元后，剩余金额为：`N - (M5 * 5)`。
* 在**剩余金额**的基础上，计算 2 元的数量。
* 选完 2 元后，剩下的金额自然就是 1 元的数量。

### 2. 运算符 `//`（整除）
题目中使用的是 `//`，它会丢弃小数部分，只保留整数商。
* 如果直接用 `N // 2`（选项 A），则忽略了已经扣除的 5 元部分，导致计算结果远超实际总额。

### 3. 逻辑推导步骤
1. **计算 5 元数量**：`M5 = N // 5`。
2. **计算 2 元数量**：需要先算出扣除 5 元后的钱 `(N - M5 * 5)`，再整除 2。
    * 代码：`M2 = (N - M5 * 5) // 2`
3. **计算 1 元数量**：总额扣除所有 5 元和 2 元的总面值。
    * 代码：`M1 = N - M5 * 5 - M2 * 2`

---

## ❌ 错因分析

你在选择 A 时，可能存在以下逻辑盲区：
1. **忽略了动态余额**：计算 `M2` 时直接使用了原始总额 `N`。在程序逻辑中，变量 `N` 本身没有自动减少，需要通过减法或取模手动计算剩余部分。
2. **单位混淆（数量 vs 金额）**：在计算 `M1` 时，直接用 `N - M5 - M2`。注意 `M5` 是硬币的**数量**，而 `M5 * 5` 才是这些硬币代表的**总价值**。

---

## 💡 知识拓展：取模运算符 `%` 的妙用

在 Python 中，处理此类“剩下的钱”的问题，使用 **取模运算符 `%`** 会更优雅：
```python
M5 = N // 5
remainder = N % 5  # 这一步直接得到了扣除 5 元后剩下的余额
M2 = remainder // 2
M1 = remainder % 2  # 剩下的就是 1 元的数量
```

---

## 📅 避坑指南：逻辑严谨性

* **括号优先**：在 `(N - M5 * 5) // 2` 中，必须先算减法再算整除，所以括号不可省略。
* **找零策略**：必须**从大面额到小面额**。如果先算 1 元，虽然能凑出总额，但硬币张数会极多，不符合题目“最少币种”的要求。

---

> **结论**：本题考查对变量更新和算术逻辑的掌握。牢记：**下一阶段的输入必须是上一阶段扣除后的余数**。
