# 🐍 Python 基础知识：循环嵌套中的缩进逻辑与变量作用域

在 Python 中，**缩进（Indentation）** 决定了代码所属的层级。即便代码中存在复杂的内层循环或条件判断，如果计数变量所在的缩进与内层逻辑无关，其执行次数将仅受所在层级的影响。

---

## 📝 题目回顾

**10、下面 Python 代码执行后的输出是（）**

```python
loopCount = 0
for i in range(10):
    for j in range(i):
        if i * j % 2:
            break
    loopCount += 1
print(loopCount)
```

* A. 25
* B. 16
* C. **10 (√)**
* D. 55（原选项 D 缺失，根据解析推断）

**解析**：
* **你的答案**：D
* **正确答案**：C (10)

---

## 🔍 核心考点深度拆解

### 1. 缩进决定归属
这是本题最大的“陷阱”。观察 `loopCount += 1` 的位置：
* 它与内层循环 `for j in range(i):` 处于**同一缩进层级**。
* 这意味着它是 **外层循环** `for i in range(10):` 的直接子语句。
* 它**不属于**内层循环 `j`，也**不受** `if i * j % 2` 或 `break` 的控制。

### 2. 执行流程推演

1.  外层循环 `i` 从 `0` 循环到 `9`，总计 **10 次**。
2.  在每一轮外层循环中：
    * 先执行完整的内层 `j` 循环（无论内层循环执行了多少次，或者是否被 `break` 提前终止）。
    * 内层循环结束后，执行一次 `loopCount += 1`。
3.  因此，`loopCount` 的自增次数完全等于外层循环的迭代次数。

### 3. 数学等式
$loopCount = \sum_{i=0}^{9} 1 = 10$

---

## ❌ 错因分析

你可能被复杂的内层逻辑干扰了判断：
* **干扰项分析**：内层的 `if i * j % 2: break` 看起来很高级，但由于它和 `loopCount += 1` 并不在一个“户口本”上（不在同一个缩进块内），它就像是邻居家的事，完全不影响 `loopCount` 的计数。
* **视觉误差**：如果代码写成下面这样，答案才会受到内层影响：
  ```python
  for i in range(10):
      for j in range(i):
          loopCount += 1  # 这样才会累加所有 i*j 的次数
  ```

---

## 💡 知识拓展：Break 的作用范围

在 Python 中，`break` 语句具有“就近原则”：
* **只跳出当前层**：`break` 只能跳出它所属的那一层循环（即内层 `j` 循环）。
* **对上层无影响**：跳出内层循环后，控制流会回到外层循环的下一条语句。在本题中，就是回到 `loopCount += 1` 这一行。

---

## 📅 避坑指南：快速扫图法

当你看到循环嵌套题目时，第一步不是计算，而是**画垂直线**：
1.  从 `for i` 的开头画一条垂直向下的虚线。
2.  看看哪些语句的开头在这条线上。
3.  在本题中，你会发现 `for j` 和 `loopCount += 1` 都在这条线上，说明它们是**平级**的。
4.  **结论**：不管 `for j` 里面闹成什么样，只要 `for i` 跑 10 次，`loopCount` 就加 10 次。

---

> **结论**：Python 是靠缩进“说话”的语言。分析循环题目时，**缩进优先级高于逻辑复杂度**。
